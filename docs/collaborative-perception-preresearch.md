# 多机协同感知预研路线（基于 Be My Eye）

撰写日期：2026-11-16。状态：**预研计划，尚无任何实现**。本文不描述已有能力；文中每个阶段的"完成判据"通过之前，不得据此声明对应功能可用。

本文把论文《Be My Eye: Learning to See Beyond a Robot's Own Perspective》（arXiv:2611.12295）的思路转成本项目可分阶段验证的预研路线。当前 MQTT 传输是临时方案，本路线不把它的带宽和经 broker 中转的拓扑当作约束；机间通道按局域直连设想，具体传输在阶段 1 再定。

## 1. 论文要点与可借鉴范围

论文让两台机器人互传"按任务压缩过的视觉 token"，而不是原始图像或通用视觉特征。以下数字来自 arXiv 页面的自动提取，引用前需对照原文核对。

| 项 | 论文做法 |
|---|---|
| 压缩 | 冻结的视觉、文本编码器提特征，K 个可学习查询（默认 K=32）聚合成 K 个 token |
| 第一阶段训练 | 任务加权的未来视觉特征预测，加上按任务进度构造的软标签对比学习 |
| 第二阶段训练 | token 放进对方策略的输入前缀，对方的动作损失反传到发送方编码器 |
| 推理 | 两机共享编码器参数，各自编码、互换 token、各自出动作，无固定领导者 |
| 结果 | 遮挡目标选择 88.9%（不共享 38.9%，160 个通用 token 72.2%）；通信量 144 KiB/步 |
| 消融 | 去掉进度对比学习后过程得分从 100% 降到 68.9%；K=4 时仍有 90.5% |

本项目借鉴三点：

1. **按接收方决策需要决定传什么**，而不是按固定频率转发原始状态。
2. **任务进度是最有价值的共享信号**，消融中它的贡献远大于未来预测。
3. **token 数量可调**，协作所需信息量很小，适合按链路分档。

不能照搬的部分：

- 论文是两台同构双臂机器人做桌面操作，策略是预训练的 π0.5。本项目是无人车、无人机、Go2 和人形的移动集群，动作空间是底盘速度。
- 论文只验证了两机同步通信，任务一仅 18 次试验，没有公开代码，损失权重、预测时域和数据量均未给出。
- 超过两台、异构机器人、选择性通信，作者列为未来工作。这些正是群体智能必须回答的问题，在阶段 4 作为本项目自己的研究点。

## 2. 需要先补的前置能力

下表的"现状"均以当前仓库文档为准。

| 前置能力 | 现状 | 需要补什么 | 最早用到的阶段 |
|---|---|---|---|
| 共享场景多机仿真 | 已有：`run_pcd_go2.sh --robots N` 在一个 MuJoCo 模型里跑 2–8 台 Go2，各有 `cmd_vel` 和 ONNX 行走策略，见 [庭院场景](pcd-go2-scene.md#多机) | 可放置的遮挡物和目标物，以及可脚本化的场景重置 | 0 |
| 仿真感知 | 没有仿真相机，见 [MuJoCo 说明](mujoco.md) | 阶段 0–1 用仿真真值加视线判定代替；阶段 2 起需要每台机器人的仿真相机图像话题 | 0 / 2 |
| 仿真接入统一接口 | 仿真链路未连接统一 runtime、SDK、采集计划和训练动作标签，见 [数据流](data-flow.md) | 至少让 `chaos_data` 能录到仿真里每台机器人的观测和发出的速度指令 | 2 |
| 机间通道 | 没有。机器人只经 MQTT 连平台，默认不转发图像和点云 | 一个带版本的机间消息契约：发送方、任务标识、源时间戳、有效期、载荷 | 1 |
| 多机同步采集与导出 | `chaos_data` 按单资产建 session，episode 是单资产任务区间，见 [训练数据规范](training-data.md) | 把多台机器人的 session 关联成一个联合 episode，在同一时间网格上对齐各机观测和动作 | 2 |
| 训练链路 | 没有 LeRobot 适配器、训练器和评估流程 | 独立训练环境，读取联合 episode | 3 |
| 机载推理 | `model manifest` 只是预留约定，没有加载器和资产 `policy` 配置 | 策略进程经 `chaos_sdk` 提交速度，遵守租约、有效期、限幅和停止 | 3 |
| 跨机时间同步 | 已有主机级 chrony 准入和时间质量日志 | 真机阶段要求各机同源授时；仿真阶段各机同主机，不构成问题 | 4 |

多机联合 episode 沿用单资产导出的因果规则：网格时刻 `t` 的观测必须满足 `source_ns <= t` 且 `receive_ns <= t`。对方共享的信息属于观测，同样受此约束，不能用对方未来才发出的摘要补当前时刻。

## 3. 仿真验证场景

场景都在共享碰撞场景的多机 Go2 仿真里搭建。它们按"不共享就做不好"的原则设计，这样共享信息的作用才能和策略本身的能力分开。

### 场景 A：遮挡目标选择

对应论文任务一。三个候选位置之一放有目标，观察机 A 有视线，执行机 B 被墙挡住。B 需要走到目标所在的位置。

- 不共享时 B 的理论水平是三选一，约 33%。
- 目标位置每次随机，A 和 B 的出生点带扰动。

### 场景 B：无指令跟随

对应论文任务二。只有领导机收到目标指令；跟随机没有指令，也没有触发信号，必须从对方共享的信息推断去哪里、何时出发。两机在各回合交替担任领导。

- 不共享时跟随机无法完成，成功率应为 0%。若不为 0%，说明场景泄漏了信息，需要先修场景。

### 场景 C：窄道队列

本项目特有。使用 `--layout line` 的单列编队通过窄道，前车能看到前方障碍，后车视线被前车遮挡。后车需要提前减速或绕行。

- 指标除成功率外，加上碰撞次数和通过时间。
- 这个场景用来检验共享信息在连续控制中的时效性，而不只是一次性的离散选择。

### 场景 D：三台以上的分区搜索（阶段 4）

三到八台机器人在庭院场景中寻找若干目标。检验多路共享信息的聚合，以及"跟谁通信"的选择。

### 统一的评估口径

- 每种方法每个场景至少 100 次随机试验，报告成功率和置信区间。论文 18 次试验下 88.9% 对 72.2% 只差 3 次成功，本项目不用这种样本量下结论。
- 每次都同时跑三条基线：不共享、共享仿真真值（上界）、共享未压缩的完整观测。
- 记录每步共享的字节数，并在注入延迟和丢包的条件下重复评估。
- 仿真结论不外推到真机。

## 4. 分阶段目标

### 阶段 0：场景与基线

目标：搭出场景 A、B、C，并证明它们确实需要共享信息。

- 用仿真真值加视线判定生成每台机器人"看得见什么"，不依赖仿真相机。
- 实现规则式的执行策略，跑通"不共享"和"共享真值"两条基线。

完成判据：三个场景中，"共享真值"的成功率明显高于"不共享"，且场景 B 的"不共享"为 0%。

### 阶段 1：手工定义的感知摘要

目标：不用任何学习模型，验证借鉴点 1 和 2。

- 定义机间消息契约和一个手工摘要，至少包含：目标是否可见及其位置、最近障碍、任务进度。
- 机间通道先用同一 ROS Domain 内的话题实现，传输方式不写死在契约里。
- 做摘要字段的消融，重点确认任务进度字段的贡献是否与论文一致。

完成判据：手工摘要在三个场景中达到"共享真值"基线的大部分成功率；得到每个字段的贡献和每步字节数。这组结果是后续学习式方法必须超过的基线。

### 阶段 2：多机同步采集

目标：产出能训练的多机联合数据集。

- 给仿真加每台机器人的相机图像话题。
- 让采集能录到仿真中各机的观测和速度指令，并导出联合 episode。
- 用阶段 1 的规则策略批量生成演示数据。

完成判据：联合 episode 通过与单资产导出同等的时间和序号检查；对方的共享信息在数据中满足因果约束。

### 阶段 3：学习式压缩 token

目标：复现论文的核心机制，并与阶段 1 的手工摘要比较。

- 按论文两阶段训练：先学任务相关的压缩，再接入策略联合优化。
- 策略模型需要先做选择：论文用 π0.5，本项目动作空间是底盘速度，较小的模仿学习策略可能已经够用。这个选择在本阶段开始时用小规模实验决定。
- 复现三项关键消融：去掉进度对比学习、第二阶段冻结编码器、改变 token 数量 K。

完成判据：在相同字节预算下，学习式 token 的成功率不低于手工摘要；三项消融的趋势有明确结论，无论是否与论文一致。若学习式方法没有超过手工摘要，如实记录并在此停下重新评估方向。

### 阶段 4：群体扩展与真机

目标：回答论文没有回答的问题。

- **多于两台**：在场景 D 中研究多路 token 的聚合，以及按需选择通信对象。
- **异构**：论文两机共享编码器参数。无人车、无人机、Go2 的视角和动作空间不同，需要验证共享参数是否仍然成立，或是否需要按型号区分编码器。
- **链路分档**：利用 K 可调的性质，按链路质量切换 token 数量。
- **真机**：先在两台 Go2 上复现场景 A。真机策略输出经 `chaos_sdk` 提交，不绕过控制租约、有效期、限幅和停止。

完成判据：各项分别验收。仿真中多机结论成立不等于真机集成完成。

## 5. 风险与待决问题

- **任务迁移可能不成立。** 论文的收益来自操作任务中的细粒度遮挡。移动任务中，手工摘要可能已经足够好，学习式压缩的增量可能很小。阶段 1 的结果会直接回答这一点。
- **仿真图像与真机差距。** 现有点云和高斯场景是静态几何代理，不是照片级渲染；在其上训练的视觉编码器迁移到真机的效果未知。
- **论文无法精确复现。** 关键超参数和数据量未公开，阶段 3 的结果只能说明"该机制在本项目设定下是否有效"，不能说明是否复现了论文。
- **共享信息的失效语义。** 对方的 token 过期、丢失或来自时钟不可信的主机时，接收方策略必须有明确行为。这与现有速度指令的有效期、观测龄期检查是同一类问题，应在阶段 1 的消息契约里一并定义。
- **待决**：机间通道的长期传输方案；策略模型规模；真机阶段的算力是否放在机载主机。
