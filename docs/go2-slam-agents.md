# Notes for agents

- Build: `./scripts/build_slam.sh` (never `src/livox_ros_driver2/build.sh`, it wipes build/ and install/).
- Tests: `source /opt/ros/jazzy/setup.bash && colcon test --packages-skip livox_ros_driver2 && colcon test-result --all`.
- `src/fast_livo2` is GPL-2.0, ported from hku-mars/FAST-LIVO2 0d2c034. Keep estimator code close to upstream; list every behavioural change in `src/fast_livo2/UPSTREAM.txt`. Do not copy rpg_vikit or Sophus code into it.
- `base_link` is the Mid-360 built-in IMU; `trunk` is the body centre used by body boxes and the stair planner. `base_to_livox` in `go2_bringup/urdf/go2_sensors.urdf` must equal `extrin_calib.extrinsic_T` in `fast_livo2/config/go2_mid360.yaml` and `grid_map.lidar_extrinsic_t*` in `go2_bringup/config/scan_planner.yaml`.
- Nav2 was replaced by SCAN-Planner (`src/scan_planner`, Apache-2.0, vendored from xiaoqi371317/SCAN-Planner-Ros2 103bce4; keep changes listed in `src/scan_planner/UPSTREAM.txt`). Its packages live at `src/scan_planner/{bspline_opt,path_searching,plan_env,plan_manage,traj_utils,scan_planner_msgs}` — colcon recurses into them. It plans in the odom frame: `body_pose`=/body_pose (trunk pose published by go2_slam_backend from the URDF TF), `sensor_pose`=/aft_mapped_to_init, `cloud`=/cloud_registered (odom frame, body-cropped by fast_livo2; its IMU->lidar extrinsic is configured in `grid_map.lidar_extrinsic_t*`). Route input is /initial_path (odom frame, produced by go2_terrain_planner's route_topic, re-sent after map->odom corrections). Output is planar /cmd_vel via closed_loop_controller; nothing bridges it to the Unitree API yet.
- No real sensor data on this machine. A synthetic Mid-360 publisher (box room, static IMU, optional camera) is enough to smoke-test the whole chain.
